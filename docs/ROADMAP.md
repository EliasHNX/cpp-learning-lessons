# Flexible learning roadmap

The goal is to develop C++ fundamentals, modern C++ fluency, and independent problem solving through varied small programs. This is a sequence of topics rather than a calendar deadline.

| Stage | Topic | Example work | Current state |
|---|---|---|---|
| 1 | Objects, references, ownership | Character health, copies, lifetime, unique ownership | Implemented examples |
| 2 | State and conditions | Finite-ammo gun, read-only borrowing, transfer limits | Implemented examples |
| 3 | Array reasoning | Distinct extrema, counts/sums, ranges and runs | Implemented examples |
| 4 | Pair counting and enums | Equal-value pairs; enum-driven actions | Implemented simple versions |
| 5 | Interactive console behavior | Keyboard choices, persistent state, invalid input recovery | Implemented example |
| 6 | Frequency counting | First unique value; compare pair-counting approaches | Upcoming |
| 7 | Practical organization | Small inventory, functions or class refactor; const and ownership choices | Upcoming |
| 8 | Prefix sums | Efficient repeated range queries | Upcoming |
| 9 | Sorting and two pointers | Find target-sum pairs | Upcoming |
| 10 | Stacks | Balanced brackets and state traces | Upcoming |
| 11 | Graph modelling and DFS | Reachability, components, flood fill | Upcoming |
| 12 | BFS and binary search | Unweighted paths; monotonic boundaries | Upcoming |
| 13 | Modern C++ practice | RAII, movable ownership and reusable containers in a small project | Ongoing / upcoming |
| 14 | Combine and review | Small playable prototype and independent problems | Upcoming |

Implemented means example code exists, not that every concept has been independently mastered. Follow-up work should include recalling the idea later and solving a fresh problem without a supplied recipe.

Alternate algorithm work with debugging, small console/game-related features and modern C++ practice. Use at most a small number of close variants before moving to a genuinely different task.

For each task: understand it, work examples, propose a simple correct method, estimate its work, implement, test, and explain the result. Add new features to solve concrete needs rather than as a syntax checklist.
